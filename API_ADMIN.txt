KAAMGHAR ADMIN API
==================

BASE URL
--------
Direct Express API:       http://localhost:4000
Admin web app proxy:      http://localhost:3001

Use /api/... on port 3001 in the browser, or
http://localhost:4000/api/... in Postman.

AUTHENTICATION
--------------
Admin login sets a separate HttpOnly kg_admin_session cookie. Send it on
/api/admin/... requests. Do not send an admin password as a bearer token.
Postman should save and resend the cookie automatically.

All JSON requests:
Content-Type: application/json

1. ADMIN LOGIN
--------------
POST /api/admin/auth/login
Auth: Not required

Payload:
{
  "email": "admin@example.com",
  "password": "replace-with-admin-password"
}

Success: 200 OK
Set-Cookie: kg_admin_session=...; HttpOnly; SameSite=Strict
{
  "message": "Welcome back.",
  "user": {
    "id": "3123456789abcdef01234567",
    "name": "KaamGhar Admin",
    "email": "admin@example.com",
    "phone": "+91 90000 00000",
    "role": "admin"
  }
}

2. CURRENT ADMIN / LOGOUT
-------------------------
GET /api/admin/auth/me
Auth: kg_admin_session cookie
Success: 200 OK

    "name": "KaamGhar Admin",
    "email": "admin@example.com",

    "pendingDocuments": 1,
    "bookings": 8,
    "completedRevenue": 1798,

  "recentBookings": [
    {

      "customerName": "Aanya Sharma",
      "status": "pending",
      "address": "12 Example Road, Chandigarh",

4. SERVICE CATEGORIES
---------------------
GET /api/admin/categories
Auth: Admin cookie
Response: 200 OK
{
  "categories": [
    { "name": "Plumber", "label": "Plumbing", "price": 500 }
  ]
}
Existing and newly created categories start at ₹500. Editing a category price
does not change professional-specific hourly rates.

POST /api/admin/categories
Auth: Admin cookie
Payload:
{
  "name": "Plumber",
  "label": "Plumbing"
}
label is optional; when omitted, it defaults to name.
New categories start at ₹500.

Success: 201 Created
{
  "category": { "name": "Plumber", "label": "Plumbing", "price": 500 }
}

PATCH /api/admin/categories/:name
Auth: Admin cookie
Payload: { "price": 750 }
Updates the category price (₹1–₹1,000,000).

DELETE /api/admin/categories/:name
Auth: Admin cookie
Deletes a category if no professional is assigned to it. Returns 409 if it
is still in use. Deleted categories stay deleted after a backend restart and
can be recreated with the same name.

      "category": "Plumber",
      "city": "Chandigarh",
      "price": 1000,
      "approvalStatus": "pending",

      "verificationDocuments": [],

PROVIDER PAYOUT CLEARANCE
-------------------------
POST /api/admin/professionals/:id/payouts/clear
Auth: Admin cookie
Payload (reference is optional):
{
  "reference": "BANK-UTR-EXAMPLE"
}

Success: 200 OK
{
  "message": "Payout marked as cleared.",
  "payout": {
    "amount": 7000,
    "bookingCount": 3,
    "clearedAt": "2026-11-18T10:00:00.000Z",
    "reference": "BANK-UTR-EXAMPLE"
  }
}
This records a manual payout for all currently pending paid bookings for the
professional. It does not initiate a bank or Razorpay transfer.

7. APPROVE OR REJECT A PROFESSIONAL
-----------------------------------
PATCH /api/admin/professionals/:id/status
Auth: Admin cookie

Payload to approve:
{
  "status": "approved"
}

Payload to reject:
{
  "status": "rejected"
}

Success: 200 OK
{
  "message": "Professional approved.",
  "worker": {
    "_id": "1123456789abcdef01234567",
    "approvalStatus": "approved",
    "available": true
  }
}
Documents are optional. If documents have been uploaded, every one must be
verified before approval. An approved and available profile can appear in the
public professional search.

10. LIST AND ACTIVATE USER ACCOUNTS
-----------------------------------
GET /api/admin/users?role=customer
GET /api/admin/users?role=worker
GET /api/admin/users
Auth: Admin cookie
role is optional: customer or worker. Without role, customers and approved
providers are returned.
Provider accounts include their total, pending, and cleared payment amounts
inside worker.earnings. The Users tab offers a Payout button next to providers
with a pending amount; after a successful clear, pending decreases and
Payment received increases.

Success: 200 OK
{
  "users": [
    {
      "_id": "0123456789abcdef01234567",
      "name": "Aanya Sharma",
      "email": "aanya@example.com",
      "phone": "+91 98765 43210",
      "role": "customer",
      "active": true,
      "createdAt": "2026-11-17T09:00:00.000Z"
    }
  ]
}

PATCH /api/admin/users/:id/status
Auth: Admin cookie
Payload:
{
  "active": false
}
Set active to true to reactivate an account.

Success: 200 OK
{
  "message": "Account deactivated.",
  "user": {
    "_id": "0123456789abcdef01234567",
    "name": "Aanya Sharma",
    "email": "aanya@example.com",
    "phone": "+91 98765 43210",
    "role": "customer",
    "active": false
  }
}

11. BOOKINGS
------------
GET /api/bookings
PATCH /api/bookings/:id/status
These shared endpoints use the kg_session cookie. The admin dashboard instead
uses GET /api/admin/bookings with kg_admin_session to list up to 500 bookings
and their payment details.
New bookings appear in the overview and provider/customer lists only after
Razorpay payment is verified; paid cancellations are flagged for a
support-managed refund.

PATCH payload:
{
  "status": "confirmed"
}
Valid status values: confirmed, completed, cancelled. Admin can set any of
these; customer/provider transitions are ownership- and status-limited.
Success: { "message": "Booking updated.", "booking": { ... } }

COMMON ERRORS
-------------
400 Bad Request: invalid payload, status, id, or query.
401 Unauthorized: missing/invalid admin cookie or invalid credentials.
403 Forbidden: authenticated account is not an admin.
404 Not Found: professional, document, or user does not exist.
409 Conflict: duplicate category/email, or a document is not verified.
Responses use JSON such as:
{
  "message": "Choose a valid professional status."
}
